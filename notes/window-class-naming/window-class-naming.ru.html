Соглашение об именовании оконных классов — как мы пришли к этому решению

В Total Commander может быть загружено сразу несколько наших плагинов — SnipClip, RecentTab, другие в будущем — все в одном процессе TC. Если плагин регистрирует фоновое окно (как ClipWatch у SnipClip, отслеживающее изменения буфера обмена) под общим именем вроде "BackgroundWindow", другой одновременно работающий плагин может случайно использовать точно такое же имя — Windows знает оконные классы только в масштабе всей системы, а не отдельно для каждого плагина.

Поэтому каждое окно и каждое именованное сообщение Windows, которое плагин регистрирует сам, получает префикс с именем плагина: TC_SnipClip_BackgroundWnd_v1 вместо просто BackgroundWnd. Это предотвращает конфликты между одновременно работающими плагинами, причём плагинам вообще не нужно согласовывать это друг с другом во время выполнения — достаточно самого имени.

Номер версии в конце (_v1) добавлен намеренно: если позже изменится смысл этого оконного класса или сообщения (например, новый формат сообщения), новый номер версии позволит чисто разделить это изменение, не запутывая старые, всё ещё работающие экземпляры плагина.

Где это применяется в SnipClip

- Фоновое окно ClipWatch: TC_SnipClip_BackgroundWnd_v1

- Зарегистрированное сообщение между WFX и WLX (редактирование в Lister → история): SnipClip_SuppressNextCapture

Оба имени находятся централизованно в snip_shared.h, поэтому WFX и WLX гарантированно используют одно и то же значение, не дублируя его в двух местах кода.
