Setting up Cloud Upload (ImgBB & Pastebin)

The Upload button in the Alt+Enter dialog sends a screenshot to ImgBB, or a text entry (history, StickySnip, Textbaustein) to Pastebin, and writes the returned URL straight to the clipboard. Both are completely off by default — nothing leaves this PC until you explicitly set it up.

The master switch

One single switch decides whether anything can be uploaded at all, independent of the individual services:

[cloud_upload]
Enabled=0

Set this to 1 first, then the per-service settings below take effect. The button itself stays completely hidden in the dialog as long as Enabled=0 or the relevant API key is missing — it never appears just to fail.

Setting up ImgBB

Get a free key at api.imgbb.com, enter it in the ini:

[cloud_upload_imgbb]
ApiKey=YOUR_IMGBB_KEY
ExpirationSec=0

ExpirationSec=0 (default) means images stay online permanently. A value between 60 and 15552000 (seconds) instead makes them disappear automatically after that time.

Setting up Pastebin

Two different keys here, easy to mix up:

  • Dev key — your personal, fixed API key. Found at pastebin.com/api (while logged in), the "Your Unique Developer API Key" box. Needed for every single call.
  • User key — confirms a paste belongs to your logged-in account (private pastes, your own paste history, Power Member perks). Without it, pastes are posted as a guest — still works, just without those benefits.

You get the user key once, via a login call. Per Pastebin's own documentation it doesn't expire unless a new one is generated — not a recurring step. Run this once in PowerShell:

$response = Invoke-RestMethod -Uri "https://pastebin.com/api/api_login.php" -Method Post -Body @{
    api_dev_key = "YOUR_DEV_KEY"
    api_user_name = "YOUR_USERNAME"
    api_user_password = "YOUR_PASSWORD"
}
$response

That last line, $response, matters — without it PowerShell only stores the result, it doesn't display it. The value printed is your user key, goes into the ini:

[cloud_upload_pastebin]
ApiKey=YOUR_DEV_KEY
UserKey=THE_RESULT_FROM_ABOVE
Private=1
ExpireDate=N
Your username and password aren't stored anywhere by this one-off call — not by the plugin, not in any log file. They're only used for that one login moment. Still, don't accidentally copy your PowerShell history somewhere afterward.

Private= controls visibility of new pastes: 0=public, 1=unlisted (default), 2=private. ExpireDate= defaults to N (never) — or Pastebin's own codes: 10M/1H/1D/1W/2W/1M/6M/1Y.

The button in the Alt+Enter dialog

Once both conditions are met (master switch on, matching key set), "Upload" appears next to "OK". Opening the dialog immediately runs a quick connectivity check in the background (not a real upload, just a reachability probe):

  • Checking connection… — probe running, button still disabled
  • Connected — button active, clicking starts the real upload
  • Not reachable — button stays disabled, no upload attempt that would only fail anyway
  • Uploading… — upload in progress, doesn't block the dialog
  • Uploaded, URL copied: … — done, URL is already on the clipboard, no further click needed
  • Failed: … — with a reason, button clickable again for another attempt

Security note

All keys sit in plain text in SnipClip.ini — same as every other setting this plugin stores. There's no encrypted storage for them. Sharing, backing up, or syncing this ini file passes the keys along with it.
