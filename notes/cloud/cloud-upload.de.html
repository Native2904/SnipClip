Cloud-Upload (ImgBB & Pastebin) einrichten

Der Upload-Button im Alt+Enter-Dialog schickt einen Screenshot zu ImgBB oder einen Text-Eintrag (Verlauf, StickySnip, Textbaustein) zu Pastebin und schreibt die zurückgegebene URL direkt in die Zwischenablage. Beides ist standardmäßig komplett aus — nichts verlässt diesen Rechner, bis du es explizit einrichtest.

Der Hauptschalter

Ein einziger Schalter entscheidet, ob überhaupt irgendetwas hochgeladen werden kann, unabhängig von den einzelnen Diensten:

[cloud_upload]
Enabled=0

Erst auf 1 stellen, dann greifen die Einstellungen der einzelnen Dienste unten. Der Button selbst bleibt im Dialog komplett unsichtbar, solange Enabled=0 ist oder der jeweilige API-Key fehlt — er erscheint nie, nur um dann zu scheitern.

ImgBB einrichten

Kostenlosen Key holen auf api.imgbb.com, dort in die ini eintragen:

[cloud_upload_imgbb]
ApiKey=DEIN_IMGBB_KEY
ExpirationSec=0

ExpirationSec=0 (Standard) heißt: Bilder bleiben dauerhaft online. Ein Wert zwischen 60 und 15552000 (Sekunden) lässt sie stattdessen automatisch nach der angegebenen Zeit verschwinden.

Pastebin einrichten

Hier gibt es zwei unterschiedliche Schlüssel, leicht zu verwechseln:

  • Dev-Key — dein persönlicher, fester API-Schlüssel. Zu finden auf pastebin.com/api (eingeloggt), Kasten "Your Unique Developer API Key". Wird bei jedem Aufruf gebraucht.
  • User-Key — bestätigt, dass ein Paste zu deinem eingeloggten Account gehört (private Pastes, eigene Paste-Historie, Power-Member-Vorteile). Ohne ihn wird als Gast gepostet — funktioniert auch, aber ohne diese Vorteile.

Den User-Key holst du dir einmalig über einen Login-Aufruf. Er läuft laut Pastebins eigener Dokumentation nicht ab, solange kein neuer erzeugt wird — kein wiederkehrender Schritt. Einmal in PowerShell ausführen:

$response = Invoke-RestMethod -Uri "https://pastebin.com/api/api_login.php" -Method Post -Body @{
    api_dev_key = "DEIN_DEV_KEY"
    api_user_name = "DEIN_BENUTZERNAME"
    api_user_password = "DEIN_PASSWORT"
}
$response

Die letzte Zeile $response ist wichtig — ohne sie speichert PowerShell das Ergebnis nur, zeigt es aber nicht an. Der ausgegebene Wert ist dein User-Key, kommt in die ini:

[cloud_upload_pastebin]
ApiKey=DEIN_DEV_KEY
UserKey=DAS_ERGEBNIS_VON_OBEN
Private=1
ExpireDate=N
Benutzername und Passwort landen bei diesem einmaligen Aufruf nirgendwo dauerhaft — nicht im Plugin, nicht in einer Log-Datei. Sie werden nur für den einen Login-Moment gebraucht. Trotzdem: PowerShell-Verlauf danach nicht versehentlich irgendwo weiterkopieren.

Private= steuert die Sichtbarkeit neuer Pastes: 0=öffentlich, 1=unlisted (Standard), 2=privat. ExpireDate= steht standardmäßig auf N (nie) — alternativ Pastebins eigene Codes: 10M/1H/1D/1W/2W/1M/6M/1Y.

Der Button im Alt+Enter-Dialog

Sobald beide Bedingungen erfüllt sind (Hauptschalter an, passender Key gesetzt), erscheint "Hochladen" neben "OK". Beim Öffnen des Dialogs läuft im Hintergrund sofort ein kurzer Verbindungstest (kein echter Upload, nur ein Erreichbarkeits-Check):

  • Prüfe Verbindung… — Test läuft, Button noch deaktiviert
  • Verbunden — Button aktiv, Klick startet den echten Upload
  • Nicht erreichbar — Button bleibt deaktiviert, kein Upload-Versuch, der ohnehin nur scheitern würde
  • Wird hochgeladen… — Upload läuft, blockiert den Dialog nicht
  • Hochgeladen, URL kopiert: … — fertig, URL liegt bereits in der Zwischenablage, kein weiterer Klick nötig
  • Fehlgeschlagen: … — mit Grund, Button wieder klickbar für einen neuen Versuch

Sicherheitshinweis

Alle Keys stehen im Klartext in SnipClip.ini — genau wie jede andere Einstellung, die das Plugin speichert. Es gibt keinen verschlüsselten Speicherplatz dafür. Wer diese ini-Datei teilt, sichert oder synchronisiert, gibt die Keys mit weiter.
