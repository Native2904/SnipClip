Screenshots mit StickySnips verknüpfen

Ein Screenshot und eine dazugehörige Notiz sollen als zusammengehörig erkennbar sein, ohne einen Namen abtippen zu müssen. Direktes Ziehen einer Datei auf eine andere einzelne Datei unterstützt weder TC noch Windows — Ziehziele sind immer Ordner. Die Verknüpfung entsteht deshalb dadurch, dass beide Dateien im selben Unterordner liegen:

StickySnips\tcmd\Lister\
    notiz.snip
    screenshot.bmp

Der Ordnername trägt dabei die eigentliche Bedeutung — StickySnips haben sonst keinen frei wählbaren Namen, nur eine automatische Vorschau aus den ersten Zeichen des Inhalts.

Eigenständige Bild-Pins

Ein Screenshot lässt sich auch ganz ohne Notiz direkt aus ! Screenshots in eine normale, einstufige Kategorie ziehen (StickySnips\Bilder\) — genau wie Text auch. Mehrere Bilder zusammenhalten ist dann einfach eine gewöhnliche Kategorie mit mehreren Einträgen. Die Tiefe des Pfads entscheidet, welcher Fall gerade vorliegt: eine Ebene = eigenständiger Pin, zwei Ebenen = Verknüpfung.

Löschverhalten

Egal welche Seite einer Verknüpfung gelöscht wird, es löst sich nur die Verknüpfung — das jeweils andere Element bleibt vollständig erhalten. Ein gelöschtes Bild wandert zurück nach ! Screenshots, eine gelöschte Notiz hebt nur die Verknüpfung auf, das Bild bleibt bestehen. Gleiche Logik wie bei Historie↔StickySnip: Löschst du den einen, bleibt der andere unabhängig existierende unangetastet. Bei eigenständigen Bild-Pins (eine Ebene) gilt das nicht — dort wird tatsächlich gelöscht, da es dort keine Gegenseite gibt, die erhalten bleiben könnte.

Sichtbarkeit im Screenshot-Ordner

Im Sticky-Unterordner liegen beide Dateien sichtbar nebeneinander. Im ! Screenshots-Ordner dagegen liegen nur Bilder, ohne erkennbaren Bezug zu einer Notiz. Die Spalte Verknuepft zeigt dort den Namen der verknüpften Notiz (leer = unverknüpft) — technisch dieselbe Bauweise wie die bestehenden Custom-Spalten (Edited/Diff/Source/Age).

Speicherlimit

Zwei unabhängige Grenzen, weil Bildgröße stark schwankt:

[image_capture]
max_screenshots=50
max_total_size_mb=200

Wer zuerst zuschlägt, räumt den ältesten Screenshot raus.

Icons

Verknüpfte Einträge bekommen ein eigenes Kettenglied-Icon statt des Quell-App-Icons — "das ist verknüpft" ist auf einen Blick nützlicher als "das kam aus welchem Programm". Unverknüpfte Einträge zeigen stattdessen das echte Icon der Quell-Anwendung (extrahiert aus deren .exe), oder — falls die Quelle unbekannt ist oder das Programm inzwischen fehlt — ein Ersatz-Icon, standardmäßig das eingebaute schwebende Auge, per FallbackSourceIcon= auch frei durch eine eigene .ico ersetzbar.

Reihenfolge, in der ein Icon gewählt wird: verknüpft → echtes Quell-App-Icon → Ersatz-Icon → TC-Standard.
