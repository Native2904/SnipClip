# Комментарии для StickySnips и Textbaustein — как мы пришли к этому решению

StickySnips и Textbaustein часто носят короткие, малоинформативные имена — удобно при быстром сборе, но когда открыто сразу несколько записей, одного имени часто не хватает для узнавания. Решением стало дополнительное, независимое от имени поле — комментарий.

Для реализации рассматривались три пути. Настоящий файл `descript.ion` в папке плагина означал бы, что комментарий доступен только через реальную папку, а не напрямую из виртуальной панели — отклонено. Совершенно новое поле комментария с собственным интерфейсом ввода стало бы дублированием уже существующего в проекте плагина DescriptEdit, который редактирует такие же файловые комментарии — тоже отклонено. В итоге мы переиспользовали проверенный *подход* к вводу из DescriptEdit, но как самостоятельный код прямо внутри SnipClip: установка DescriptEdit не требуется, просто та же логика построена заново.

Отдельное окно ввода было неизбежно в любом случае, поскольку интерфейс `RequestProc` в TC не имеет типа "запросить произвольный текст" — только имя пользователя, пароль, целевую папку, URL, да/нет. Для режима редактирования мы ориентировались на Lister: тёмный для чтения, светлый для редактирования, Ctrl+E/Ctrl+S для переключения и сохранения. Цвета намеренно берутся из `[lister] Theme=`, а не из основной темы.

Поле комментария изначально было сделано только для Textbaustein, а затем расширено на StickySnips — оба являются курируемыми, зафиксированными записями с одной и той же проблемой узнавания. Сама история сознательно не получает комментариев: слишком много, слишком мимолётных записей, чтобы это того стоило.

Чтобы не терять общую картину, `! Kommentare` показывает все установленные комментарии одним списком, с именем или категорией перед каждым.
